## 项目概述与当前状态

CrossCheck 是 CS 437 的期末项目:戴在两只脚踝外侧的一对节点,检测翘腿和抖腿,并用振动提醒。原型已经跑通,两块板都能把红外和 IMU 数据无线传到电脑上并排查看;目前只做到采集数据,还不能判断腿的姿态;检测算法、自动提醒、省电唤醒和手机软件都还没做。

工作原理:

- **翘腿**:两个节点各有一颗红外 LED 和一个红外接收头,互相对射。两腿交叠时一方能收到另一方的红外脉冲。A 发 20 个载波周期的脉冲,B 发 40 个,接收方靠脉冲宽度分辨是谁发的,并忽略自己的发射。
- **抖腿**:每个节点的 IMU 以 100 Hz 采样加速度和角速度,抖腿在波形上是 4–8 Hz 的周期信号。
- **提醒**:每个节点有一个纽扣振动马达,目前只能从电脑手动触发。右脚已焊,左脚还没焊。

| 部分 | 状态 |
| --- | --- |
| 红外对射(A、B 互相识别) | 已上板验证 |
| IMU 100 Hz 原始数据流 | 已上板验证 |
| 蓝牙 / USB 双板监视台,数据录制 | 已上板验证 |
| 外壳 v9(Case A 左脚、Case B 右脚) | 已打印装配,两个效果都好 |
| 绑带 | 已完成 |
| 振动马达(D11) | 右脚已焊,左脚未焊 |
| 电源开关 | 还没装,目前靠插拔电池开关机 |
| 腿的姿态判断、翘腿 / 抖腿检测 | 未开始,目前只采集数据 |
| 省电与唤醒 | 未做,只做了降频等初步优化 |
| 手机软件 | 未做 |

原方案里的磁铁测距、霍尔传感器、UWB 和 ToF 都已放弃,不用再考虑。

## 接线

两个节点接线相同,电路焊在 Proto Wing 上。

| 功能 | Feather 引脚 | 接法 |
| --- | --- | --- |
| 红外 LED 驱动 | D9 | D9 → 1k → PN2222 基极;3V → 100 Ω → LED → 集电极;发射极接 GND |
| 红外接收 | D5 | TSSP77038 的 Sig 接 D5,V+ 接 3V,GND 接地 |
| 9DoF | STEMMA QT | I2C,地址 0x6A(IMU)和 0x1C(磁力计) |
| 振动马达驱动 | D11 | 右脚已焊,左脚未焊。D11 → 1k → PN2222 基极;基极另接 10k 到 GND;马达红线接 3V,蓝线接集电极;发射极接 GND;1N4001 并在马达两端,白环一端接 3V |
| 电源开关 | EN | 还没装,目前靠插拔电池开关机。计划:开关中间脚接 EN,一个边脚接 GND,另一个边脚悬空 |
| 板载 | 13、33、21、7 | 红色 LED、RGB 灯、RGB 灯电源、QT 口电源,不用接线 |

几点说明:

- **PN2222 脚位**:平面朝自己、脚朝下,从左到右是 发射极 – 基极 – 集电极。
- **电源开关**:EN 接地时 3.3V 稳压器关闭,整板断电;插着 USB 仍能充电。关机后有很小的待机电流,长期不用要拔电池。
- **马达的二极管不能接反**,接反会把 3V 短路到地。
- 马达驱动电路图:[`hardware/figures/motor_driver_circuit.png`](../hardware/figures/motor_driver_circuit.png)。图上引脚写的是 D10,实际焊的是 **D11**,固件也按 D11 写的。

叠板方式:Proto Wing 在下,架在壳里的四根柱子上,排针长的一端朝下;Feather 在上,元件面朝盖子;两板间隔 2.8 mm;电池在 Feather 上方、远离 USB 的一半。

## 固件

当前用的固件是 [`firmware/node_a`](../firmware/node_a/node_a.ino) 和 [`firmware/node_b`](../firmware/node_b/node_b.ino)(Arduino,原名 `nodeA_monitor` / `nodeB_monitor`)。两份代码只有开头的 `#define NODE 'A'` / `'B'` 不同,改一份后要同步到另一份。

烧录设置:

| 项目 | 设置 |
| --- | --- |
| Board | Adafruit Feather ESP32-S3 2MB PSRAM(对应 5477;选成 No PSRAM 会刷得进但启动不了) |
| USB CDC On Boot | Enabled |
| 需要的库 | Adafruit NeoPixel、Adafruit LSM6DS、Adafruit LIS3MDL |
| 哪块板刷哪个 | Case A(左脚)刷 `node_a`,Case B(右脚)刷 `node_b` |

串口不出现时进下载模式:按住 BOOT,点一下 Reset,松开 BOOT,再上传;传完按一次 Reset。

固件做的事:

- 每 50–70 ms 发一次 38 kHz 红外脉冲(A 约 0.53 ms,B 约 1.05 ms),并统计收到对方脉冲的次数。
- 100 Hz 读 IMU,每 10 个采样打成一行发出。
- 通过 USB 串口和蓝牙(BLE,Nordic UART 服务,设备名 `CrossCheck-A` / `CrossCheck-B`)同时输出。
- 板载 RGB 灯:蓝色 = 没收到对方,红色 = 收到对方。

输出的数据是每行一个 JSON:

| 行类型 | 频率 | 内容 |
| --- | --- | --- |
| 状态行 | USB 20 行/秒,蓝牙 5 行/秒 | `node`、红外统计(`seen` `rx` `bad` `w` `tx` `n`)、姿态(`pitch` `roll`)、磁力计、`vib`、电池(`v` `pct` `cr`) |
| IMU 批量行 | 10 行/秒,每行 10 个采样 | `{"t":毫秒,"s":[[ax,ay,az,gx,gy,gz],...]}`,加速度单位 mg,角速度单位 0.1 °/s |

可以发给板子的命令(USB 串口回车结束,或蓝牙写入):

| 命令 | 作用 |
| --- | --- |
| `v` | 马达震 0.4 秒 |
| `v1000` | 马达震 1 秒(最长 3 秒) |
| `x` | 立即停 |

旧的 sketch(`crosscheck_A/B`、`nodeA`、`nodeB`、各种 `_test`)是早期实验,放在 [`firmware/experiments/`](../firmware/experiments/)。其中 `nodeA` / `nodeB` 用的 ESP-NOW 节点间通信在当前固件里没有保留。

## 监视台

[`monitor/crosscheck_monitor.html`](../monitor/crosscheck_monitor.html) 是一个单文件网页,用电脑上的 Chrome 或 Edge 直接打开,左边显示 Node A、右边显示 Node B。不需要装任何东西。

使用步骤:

1. 两块板上电。
2. 点"添加蓝牙设备",选 `CrossCheck-A`;再点一次,选 `CrossCheck-B`。每块板要单独点一次,这是浏览器的限制。
3. 也可以用"添加 USB 设备"走串口,两种方式可以混用。用 USB 时要先关掉 Arduino 的 Serial Monitor,同一个端口只能被一个程序占用。

每个面板显示的内容:

| 区域 | 含义 |
| --- | --- |
| 红外指示灯 | 红 = 最近 300 ms 内收到过对方,蓝 = 没收到;和板上 RGB 灯同步 |
| 收到对方的脉冲 | 每秒收到的有效脉冲数,正对时约 15–20 |
| 长度不符,已丢弃 | 宽度不对的脉冲数,明显增多说明有干扰或时序问题 |
| 倾角 | 按芯片坐标轴算的 pitch / roll,还没有映射到小腿 |
| 振动马达 D11 | 显示是否在震,按钮可触发震 0.4 秒 |
| 电池 | 电压、电量,以及电量计估算的耗电速度和剩余时间 |
| 加速度 / 角速度波形 | 最近 5 秒,每秒 100 点 |
| 磁力计 | 三轴和总强度,目前没有用到 |
| 板子的其他输出 | 启动信息和 I2C 扫描结果,找不到传感器时看这里 |

面板标题旁边的"IMU xx 点/秒"正常应在 100 左右。蓝牙下明显低于 100 说明在丢包。

录制数据:点"开始录制",再点一次"停止并保存",浏览器会下载一个 `crosscheck_日期_时间.jsonl` 文件。每行是一条原始数据,外面包了节点名和电脑时间:`{"node":"A","pc":毫秒时间戳,"d":{...}}`。后面做检测算法要用的训练数据就这样采,采到的文件放进 `data/`。

## 外壳

外壳当前版本是 v9,两个壳子互为镜像:Case A 戴左脚装 Node A,Case B 戴右脚装 Node B。两个都已打印装配,效果良好。

佩戴方式:壳子在脚踝外侧,LED 朝外,盖子贴皮肤,USB 口朝下,带接收窗的端面朝上,接收窗偏向脚尖。两只脚都一样。

外形 61 × 47 mm(不含绑带耳),总厚约 28 mm。每个壳子由 body 和 lid 两件组成。

| 结构 | 位置 | 尺寸和说明 |
| --- | --- | --- |
| 支撑柱 ×4 | 底板内侧 | 托住 Proto Wing,顶端有 2.5 mm 定位销 |
| IR LED 孔 + 遮光套筒 | 外侧面中央 | 孔径 5.3 mm;套筒内径 6.4、高 5 mm,挡住 LED 尾部的漏光 |
| IR 接收窗 | USB 对面的端壁 | 4.5 × 7 mm 方孔 |
| USB-C 开口 | 端壁 | 14.9 × 9.2 mm,已按两板间隔 2.8 mm 对准 |
| 马达定位环 | 底板内侧,USB 端角落 | 内径 10.8、高 2 mm,马达用背胶贴在底板上 |
| 电源开关座 | 底板内侧,USB 端另一个角落 | 按 Adafruit 805 做的;拨杆从外侧面的凹槽里伸出,略低于外表面 |
| Reset / Boot 针孔 | 盖子 | 两个 2.2 mm 孔,用牙签或回形针戳;靠 USB 的是 Reset |
| 盖子压柱 ×2 | 盖子内侧 | 压在 Feather 靠 USB 的两个安装孔上,防止板子晃动 |
| 卡扣 ×2 | 两个短边,对角布置 | 扣臂宽约 12、厚 1.4 mm,扣入 1.0 mm;下端留了开盖用的拨片 |
| 绑带耳 ×2 | 两个长边 | 开口 22 × 5 mm |

Case A(左脚)的装配示意图:[`hardware/figures/CaseA_v9_left_assembly_diagram.png`](../hardware/figures/CaseA_v9_left_assembly_diagram.png)。零件位置取自 Onshape 装配体,Case B 是它的镜像。图里画的"9.9 mm 圆片"是马达在模型里的旧位置,实际要放进马达定位环。

Case B 不是 Case A 的单纯镜像,因为电路板本身不能镜像:

- Reset / Boot 针孔是按真实 Feather 的按键位置重新开的,所以**两个盖子不能互换**。
- IR 接收板和 9DoF 板在 Case B 里要换到对面的侧壁,并绕板子长边翻 180° 安装,元件面朝壳内。
- 9DoF 翻面后,左右脚的 IMU 有两个轴方向相反。做算法时要按左右脚分别映射坐标轴。

打印和装配注意:

- 用**黑色**耗材。浅色 PLA 对红外几乎透明,接收头会在壳内直接看到自己的 LED。
- 卡扣臂在盖子平放打印时是竖着长的,PLA 容易从根部断。建议用 PETG,或把盖子侧立打印。
- 电池不能盖住两个针孔的位置,边缘离 Boot 针孔的导向筒只有 0.7 mm。
- 盖子压柱离 Feather 板面只留了 0.1 mm。实际叠高比模型高的话盖子会扣不上,现在两个都能扣上,改叠板高度时注意这里。
- 针孔在贴皮肤的那一面,要摘下来才能按。

外壳模型是用 CadQuery 脚本在最初的 v4 STEP 上逐版修改出来的,生成脚本没有保存进项目文件夹。后续要改外壳,可以把 v9 的 STEP 导入 Onshape 直接改。

## 已知问题和容易踩的坑

还没验证的东西:

- **马达功能没上板测过。** 左脚还没焊马达。D11 的控制代码和监视台按钮是最后加的,没有编译,也没有实测。第一次刷如果编译报错,问题大概率在这部分。
- **还没有电源开关。** 开关机靠插拔电池。外壳已经留好开关座,买到 Adafruit 805 后按接线一节焊上即可。
- **续航没实测。** 按器件参数估算,500 mAh 电池在持续蓝牙传输下约 6–10 小时。监视台的电池一格会显示实测的耗电速度,拔掉 USB 跑几分钟后才准。

调试时遇到过的问题:

| 现象 | 原因和处理 |
| --- | --- |
| 编译报一堆 redefinition | 同一个 sketch 文件夹里放了两个 `.ino`。Arduino 会把它们拼成一个程序,每个 sketch 要单独一个文件夹 |
| 刷完没有串口、RGB 灯不亮 | 板型选错,或从下载模式刷完没按 Reset |
| 刷完有灯但没有串口 | USB CDC On Boot 没开;或者 Reset 后端口名变了,要重新选端口 |
| 改了代码但刷进去还是旧的 | Arduino 窗口里还开着旧内容,一保存就把磁盘上的新文件覆盖了。文件在外面被改过后,先关掉窗口(不保存)再重新打开 |
| 监视台显示"没找到 IMU" | 看日志框里的 I2C 扫描结果:应该有 0x6A 和 0x1C。只有 0x39 说明插的是 AS7341;什么都没有说明 QT 线没插好 |
| 接收板上的灯一直闪但显示没收到对方 | 它看到的是自己的 LED。固件会屏蔽自己发射期间的信号,灯闪不等于收到对方 |
| 抖腿波形上叠着一个慢慢变化的包络 | 采样率太低造成的混叠。现在 IMU 是 100 Hz 批量上传,不应再出现;如果又出现,检查是不是蓝牙在丢包 |

设计上的限制:

- 红外 LED 全功率时方向性很强,距离远了要对得很准才收得到。占空比降到约 6% 时有效距离大约 15 cm。
- IMU 的采样时刻有几毫秒抖动,因为发红外脉冲和蓝牙分包会占用主循环。看波形够用,做精确频率分析时要改成定时器采样。
- 红外脉冲宽度靠 `delayMicroseconds` 控制,理论上会受蓝牙影响。如果"长度不符"的计数明显变多,要改用硬件定时(RMT)发脉冲。
- 节点之间目前没有直接通信,两边的数据只在电脑上汇合。
